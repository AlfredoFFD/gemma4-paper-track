  changed region, 62, 62, 59, 63 (in that order) were shown every changed region, 58, 60, 59, 58 had a final

  In those arms, of the runs shown every changed region whose final patch overlapped one, 30 of 43, 31 of 41, 30

  and 24 of the 129 runs whose patch touches every changed region were not resolved.
  In experiment 18 (40 tasks), the runs shown every changed region were 8 in N, 27 in ON and 25 in OA (32 in OA

  patch overlaps a changed region 8, 11, 13, 13, and those resolved 4, 7, 5, 6.

7. JUDGMENT CALLS
  1. Runs and arms. A run is a row of the per-run table for its arm (one per task); the N rows of runs_23.csv,
     the N14 and NAF14 rows of runs_18.csv and the rows of runs_22.csv whose experiment is not 22 are left out.
     Every row kept has entered = 1 (the script stops otherwise), so every stage is counted over all stored
     runs.
  2. Shown at least one changed region (b): t_shown is a call index, not inf. The table's t_shown counts
     read_file results and shell views of one file (cat, head, tail, sed -n), so (b) is wider than 'a file read'
     in the strict sense. The tables give (c) from read_file results only, so (b) and (c) do not use the same
     views; section 1 checks run by run that no run is in (c) without being in (b).
  3. Shown every changed region (c): the table's column (the first scripts' reading) wherever the table has one,
     which is every arm; section 5 prints the second scripts' fuller count where they differ.
  4. Patch changes a file of the fix (e) and patch non-empty (d) for 23, and patch touches every changed region
     (g) for 14: derived from the raw records (section 1). The function for (g) is rederive_18.touches_every,
     which rederive_23.load_dir applies; it is that second script that already scores the N run of 14 this way.
  5. Patch non-empty (d) derived: the stored patch file has a non-blank character. A file of the fix (e)
     derived: the parsed final patch has a region (a hunk on an existing file) in a GOLD FILE; a file the agent
     creates does not count.
  6. The task without a GOLD FILE (fastapi_15661, in the four 103-task arms) stays in every count: it enters,
     and (b), (c), (e), (f), (g) are false for it. The second scripts print those stages over 102 tasks; the
     counts are the same.
  7. Nested chain (section 2): entered, then shown every changed region, then patch overlaps a changed region,
     then resolved; each share is over the runs at the stage before. The leaks count resolved runs outside the
     chain, and runs touching every changed region that are not resolved.
  8. Conversion intervals (section 3): one run per task in an arm, so resampling tasks resamples runs; the share
     is the ratio of the resampled sums (numerator and denominator drawn together), percentiles with linear
     interpolation (rederive_18.percentile); a resample with an empty denominator is dropped and counted.
  9. Endings (section 4): the table's ended column as stored. It is the first scripts' classification and can
     differ from the runner record; the differing runs are listed, not corrected.
 10. Cross-check (section 5): the second scripts' counts are read from their stored outputs by matching the
     printed lines; nothing is typed. For N of 14 two second scripts print counts (rederive_14 and the N14
     column of rederive_23); both are compared.
 11. Differences in (c) are attributed by recomputing (c) here four ways (paired or first-result loader, with or
     without shell views); a difference counts as reconciled when the first script's reading reproduces the
     table, the second scripts' reading reproduces their stored count, and (where the second script prints one)
     its own count under the first-result loader equals the table.
