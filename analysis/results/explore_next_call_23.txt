JUDGMENT CALLS AND WHERE THE WHOLE-RUN DATA FORCED ANOTHER READING
 1. Scorer: fork_states.touches with exact character caps (nodes.file_text line lengths), graph mentions not
    counted (rederive_s5.hit), and rederive_s5.opens_file for the looser outcome; both re-stated here because
    rederive_s5 runs its analysis at import. Files whose text could not be read for the caps: 0 (line caps only
    for those).
 2. Listed entries: the replay listed one queried node's neighbors from get_code_neighbors; a pushed list has up
    to two sources and up to 8 entries, already without nodes shown before (push_23). Every entry of the list is
    a candidate, not only true neighbors of one node; no swapped or decoy entry exists here.
 3. A file not opened before: a file shown by an earlier call by fork_states.shows_content (read_file of status
    ok with content; cat, sed, head, tail, grep, rg, awk, less or more with stdout), counting every call up to
    and including the READ that carried the list. The replays built this set from the steps before a fork in
    runs with no edit yet; whole runs also edit and write, and edit_file or write_file of a file do not count as
    opening it here (shows_content does not count them).
 4. An entry's span: the file and line range of the pushed list as the runner record stores it (for PH the agent
    did not see them; for N14 the would-be range from the address table), not nodes.span as in the replays.
 5. Next call: the tool call at call index p+1, p the index of the READ that carried the list (calls paired with
    their results by rederive_18.load_calls_paired). The replays sampled one call from a paused state; here the
    next call is whatever the run did, and a step with several calls counts each as its own call. Within 3
    calls: indexes p+1 to p+3. A list at the end of a run has fewer next calls.
 6. The replays excluded interface failures (malformed calls) from the denominator; here every list counts, and
    a malformed next call never meets the outcome (touches returns nothing for it).
 7. Lists: entered runs (rederive_23), all their pushed lists. The replays were early steps before any edit;
    pushed lists come at any point of a run, up to 10 per run.
 8. Paired shares: per run over its lists with at least one entry in an unopened file; a task without such a
    list in either run drops out. Pooled counts are on the same tasks.
