5. JUDGMENT CALLS (where the registration left room)
  - Arms: from the fork id suffix (:S, :S0, :S0N) of the state record each row names by (task, run, fork); the runner arm field (A for S and S0, S0N for S0N) is only checked against it.
  - Paths: everything up to the last "/workspace/" and any leading "./" is dropped, then normalized; a repository file is a .py member of data/snapshots/<task>.tgz (read directly, not through the cache helper).
  - Opened earlier: read_file with status ok and non-empty content; run_command whose stdout (top level or under details) is non-empty, crediting every operand of a cat/sed/head/tail/grep/egrep/fgrep/rg/awk/less/more segment that is a repository file (a directory operand opens nothing). fork_states.py itself was not opened.
  - Hit lines: one-file form (line:text) only when the command names exactly one repository file; otherwise path:line:text. Context lines path-line-text / line-text are counted, not scored.
  - Interface failures: runner error (error field set), no call (next_call empty), unknown tool (not one of read_file, run_command, write_file, edit_file, search_similar_code, submit_patch), malformed (arguments not an object or a required argument missing after cleaning quotes, backslashes and blanks from names). A mangled start_line is usable.
  - A mangled end_line (name equal to end_line once cleaned) is used as the end of the window for on_a_hit, as for start_line; a start_line below 1 or absent is taken as 1; an end below the start is treated as no end.
  - Shell reads: only the first pipeline (before && ; ||) counts; it must start with cat, head, tail or sed -n (a p-script a,bp / a,$p / ap) on a hit file; later stages in the pipe may only be head/tail/sed -n/cat/nl, otherwise the range is unknown and it is not a read. cat shows the whole file; no 150-line cap for shell views.
  - searches_again: a run_command whose first program is grep, egrep, fgrep, rg, ag, ack or git grep (find and search_similar_code are not counted, and appear under next tool); asks for line numbers: -n inside a short-option cluster or --line-number (rg: unless -N).
  - Q2 is decided on the point share (at most 5%), not on an interval bound; its interval is printed beside it. It uses the states complete for S and S0, with the 40-state floor and the 20-read condition both applied.
  - Pooled estimands: Y1, Y2 and C pool the replays of the states in a resample (C = Y1 count / Y2 count); a resample with no read in an arm gives an undefined C and is left out (count printed when non-zero).
  - Bootstrap: Python random.Random(15151); 2,000 resamples of states (and, separately, of tasks with all their states); percentile interval by linear interpolation at 2.5% and 97.5%. When the Q1/Q2 and Q3 state sets are the same, the same resamples serve both. R uses the Q3 resamples; a resample with a denominator not above 0 is left out and counted.
  - Q3c wording below two thirds is not given by the registration; the script then says the condition is not met.
  - Descriptive counts use every usable replay of every state (not only complete states). The split by line 150 is printed two ways: reads of a hit file by the nearest hit of the file read, and Y1 by states whose every hit file has its first hit past line 150.
