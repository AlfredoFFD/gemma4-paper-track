8. JUDGMENT CALLS
 1. A run enters if its arm has a result line for the task (the last line counts) and the error text is not an
    infrastructure failure by the rule of 14 (rederive_14.infra_kind). Each comparison uses the tasks where both
    of its runs entered, not the tasks entered in all four arms.
 2. Outcomes as in rederive_18: shown every changed region and shown a changed line count read_file results and
    shell views of one file, with every tool call paired with its own result (the registration says the rules
    are read from the registered script, which credits only the first result of a step with several calls; this
    script does not reproduce that loss, so a difference in L7 can come from it).
 3. Final patch overlaps / touches every changed region: the agent's patch parsed by the same parser, regions in
    the same file intersecting; an empty or missing patch is false. Comparisons on these and on shown every
    region use tasks with at least one GOLD FILE.
 4. Verdict: 'more' if the lower bound is strictly above 0, 'fewer' if the upper bound strictly below; with
    fewer than 34 paired tasks the verdict reads 'no verdict (too few tasks)' and the numbers are printed.
 5. Ending on the context window: the runner record's agent_ending is 'context window' (cross-checked against
    the error text of the result line, section 7).
 6. Cut (c) counts CHANGED REGIONS (hunk regions of the reference patch, before the merging into places used by
    the notes), summed over runs; 'edited when shown' is over the shown regions, 'when not shown' over the
    others. It is printed for all entered runs and for the runs that do not end on the context window.
 7. Pooling: a task-run is (task, seed). (i) uses the tasks where N, ON and OA all entered at both seeds, so
    each task gives two runs per arm. (ii) uses every entered run; a difference uses the (task, seed) pairs
    where both arms entered. A difference is the pooled share of the first arm minus that of the second, in
    points; the bootstrap resamples tasks with replacement (a task's runs at both seeds together),
    random.Random(0) afresh for each difference, 2,000 resamples, percentile interval of the ratio of sums.
 8. Section 6 restricts each arm to the tasks where it entered at both seeds, so the two columns of an arm are
    the same tasks.
 9. Note checks: N must carry no note, the other arms the note once in the first message
    (note_in_first_message); for seed 3 the note md5 recorded by the runner is compared with
    analysis/oracle_22/manifest.json.
