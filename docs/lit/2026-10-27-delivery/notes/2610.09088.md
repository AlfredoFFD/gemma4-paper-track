# RippleCP: Measuring Counterfactual Checkpoint Advantage in Coding Agents

- **arXiv:** 2610.09088 (v1, 06 Oct 2026, cs.AI)
- **Authors:** Mayur Akewar, Ravi Ranjan (Florida International University)
- **Read:** 2026-10-27, from the HTML full text (`lit.py fulltext`) plus the 16-page PDF for every figure and table.

**Verdict on overlap.** This paper is not about how an agent uses information. It measures the wall-clock value of
checkpointing a coding agent. It restores paired branches from different saved states, runs both to completion, and
compares their cost.

| Component | Overlap |
|---|---|
| C1 | Partly: SWE-bench Verified repair end to end, but with GPT-5.4 through the Codex CLI. |
| C4 | Partly: paired restore-and-continue with repetition and randomized branch order, but no seed control. The treatment is the restore point, not the action and not the content of an observation. |
| C5 | A weak echo only: the agent's own step-importance rating does not track the measured counterfactual value. |
| C2, C3, C6 | Nothing. |

## Claim

**Headline (Table 1, Sec 4).** Pooled over both strata, checkpointing saves **49.4 s per task** (95% task-bootstrap CI
34.1 to 65.5). This is net of the measured cost of creating the checkpoint.

**Two regimes (Table 1, Fig 2).** The headline splits into two regimes that differ by two orders of magnitude.

| Contrast | Marginal value | 95% CI | Protected work | Conversion |
|---|---|---|---|---|
| First checkpoint (Skip restarts from the pristine workspace) | 100.0 s | 72.4 to 131.1 | 156.5 s | 0.64 |
| One additional checkpoint, one step later | −1.1 s | −9.5 to 8.4 | 41.8 s | −0.03 |

**Recovery re-derives rather than replays (Sec 4, App G.6).** An elapsed-work placement rule (Young 1974) assumes
conversion near 1. It would therefore price the second checkpoint at 41.8 s and be wrong by that full amount.

**Proxies (Table 2).** Cheap proxies rank the measured advantage only inside the first-checkpoint stratum. For tool calls,
Spearman ρ = +0.85 (p = 0.003). They do not rank it inside the additional stratum. The agent's own importance score ranks
it negatively in the first stratum: −0.58 (p = 0.082).

## Method (enough to reproduce)

### Formulation (Sec 2)

- At a safe candidate state s_t, the agent chooses a_t ∈ {CP, SKIP}.
- Cost-to-go: J(s_t, a) = E_f[C_place(a) + L(Recover(s_t, a, f))].
  - C_place(SKIP) = 0, and C_place(CP) = the checkpoint creation cost.
  - L is the wall-clock redo time.
- Advantage: A_CP(s_t) = J(s_t, SKIP) − J(s_t, CP).
- Tokens, tool calls and success are recorded separately and never folded into J.

### Oracle (App B, Fig 1)

1. Restore to s_t from a common pre-candidate state.
2. CP materialises s_t; SKIP does not.
3. Drive both branches to the same logical failure and inject a fail-stop.
4. Recover CP from s_t. Recover SKIP from c⁻, the latest earlier checkpoint, or the pristine workspace if there is none.
   Branch order is randomized.
5. Continue to the hidden-test verifier or a fixed budget, with the same stopping rule for both branches.
6. Record redo time, repeated tokens and tool calls, correctness, and checkpoint/restore overhead.

The estimate is Â = (1/K) Σ_j [J_j(SKIP) − J_j(CP)]. The pilot uses K = 1, i.e. one frozen failure per candidate.

### Pilot design (Sec 4, App A)

**Tasks and nominal runs**
- 12 SWE-bench Verified tasks, frozen before any paired run: 4 each from django 4.2, sympy 1.12 and scikit-learn 1.3.
  - All are from the 15 min to 1 h difficulty tier, on Python 3.10.
  - Base-fail / gold-pass validation passed for all 24 expected worlds.
- One nominal trajectory per task, recorded with Codex CLI 0.147.0-alpha.6.5 running GPT-5.4 at xhigh reasoning.
  - Sandbox setting: workspace-write. Approval policy: never.
  - Each trajectory is 3 to 4 logical steps (mean 3.25). 10 of the 12 pass the verifier.

**Candidate cells**
- Safe boundaries are post-tool-return, post-commit and post-test points; there are 27.
- 24 cells were frozen: one early and one late boundary per task. In each cell, the next logical step is the failure.
  - Candidates therefore sit at steps 1 to 3, and failures at steps 2 to 4.

**Repetitions**
- Each cell gets 2 repetitions.
- A predeclared third repetition was run for each of the 5 cells whose first two paired advantages changed sign.
- Total: 53 pairs, i.e. 106 branches. Branch order was randomized: 26 CP-first, 27 SKIP-first.
- Per-branch cap: 1800 s. It was never reached; the longest branch used 463 s of agent time.

**Strata (Sec 4)**
- Early cells compare one checkpoint against none (SKIP restores the pristine workspace).
- Late cells compare one additional checkpoint against the earlier one (SKIP restores one step back).
- Redo distance is one step for CP and two for SKIP in both strata. So the strata differ by what SKIP falls back to, not
  by distance.

**Statistics**
- Task-level bootstrap over the 10 verified-endpoint tasks: 10,000 replicates, seed 20260818.
- Spearman correlations within each stratum, with two-sided permutation tests over 20,000 relabelings.

### Fork / checkpoint mechanics (the C4 questions)

**What is saved (App A)**
- An archive of the task workspace, excluding `.git`, virtualenvs and build/cache directories.
- The preserved transcript.
- "Discovered facts", which the paper never defines.

**What is not saved**
- Process state and tool-session state.
- Agent-visible state is rebuilt from the archived transcript, not from an OS image. It is never shown to be the same
  model context the agent originally had.

**RNG**
- None of it is controllable. The Codex runtime exposes no sampling seed.
- The recorded pair seed only orders the branches and schedules the runs.
- Nondeterminism is handled by repetition and randomized order, never by matching seeds (Sec 3, App A, App H).

**Replay**
- Nothing is replayed in the deterministic sense. Each branch restores into an isolated workspace, and the agent runs
  live to completion.
- The paper's central finding is exactly this: recovery is a re-derivation. The agent does not redo the protected work at
  its nominal cost (conversion 0.64 and −0.03).

**Sampling settings**
- GPT-5.4 at xhigh reasoning effort. Temperature is not reported.

**Costs**

| Item | Mean | Median | Range | Basis |
|---|---|---|---|---|
| Checkpoint creation | 4.38 s | 4.09 s | 2.50 to 6.68 s | 53 CP branches (App A) |
| Restore | 9.69 s | 6.76 s | p95 20.8 s | 106 branches (App A) |
| Archive size | 13.94 MB | 10.44 MB | 7.25 to 23.35 MB | 39 artifacts (App A) |

- One label (one CP/SKIP pair) costs 8.4 minutes of agent time (G.4).
- The whole study cost 28,125,711 re-executed tokens, 3.38 agent-hours and 3.85 branch-hours (App H).
- Money cost is not reported, because the agent ran on a subscription.

**What is measured after the fork**
- Wall-clock time to completion, plus the creation cost for CP.
- Re-executed tokens, tool calls, checkpoint bytes, restore latency, and whether the verifier passes.
- The harness has fields for "semantic rediscovery" and "divergent rework", but they were never annotated and are zero
  throughout (G.11).
- **Nothing about which files or functions the agent reads or edits next.**

**Does it ever vary the content of an observation? No.**
- The treatment is which saved state the agent resumes from.
- The CP world resumes with more transcript and more workspace edits than SKIP. So the contrast mixes preserved context
  with preserved file changes, and the paper does not separate the two.

**Noise figures useful for planning (G.4, App H)**
- Within-cell SD of the paired advantage across repetitions: 24.1 s.
- First-checkpoint cells: 33.1 s of noise against a 121.9 s effect (noise/signal 0.27).
- Additional cells: 15.0 s of noise against 14.4 s (noise/signal 1.04).
- 5 of the 24 cells flipped sign between their first two repetitions.

## Setting, data and models

- **Model:** one closed frontier model (GPT-5.4) through the Codex CLI.
- **Tasks:** 12 tasks from 3 Python repositories, all in one difficulty tier.
- **What is absent:** no context limit is discussed, there are no graph tools, and there is no training.
- **Proposed "ripple graph" (App C):** a provenance graph for later work. Its edges are command → file-write,
  file-version → test-result, build-input → build-output, and tool-result → artifact.
  - The authors say ripple features describe observable provenance, not causal influence.
  - They also say the counterfactual recovery measurement, not the graph, is the ground truth.
  - None of it is evaluated.

## Metrics (exact definitions)

- **Checkpoint advantage:** A_CP = J(SKIP) − J(CP), where J = wall-clock recovery time plus the measured checkpoint
  creation time (CP only) (Sec 2 and 3).
- **Marginal value:** the within-cell paired contrast, averaged per task over the 10 verified-endpoint tasks (Table 1).
- **Conversion:** the advantage divided by the nominal work the checkpoint protects, i.e. step k's nominal duration
  (Table 1, G.6).
- **Proxy ranking:** within-stratum Spearman correlation (n = 10) with permutation p-values (Table 2).

## Limitations

**The authors' (Sec 6, App H)**
- Trajectories are only 3 to 4 steps, with about 74% of the work in step 1, so the placement question barely arises.
- The "first" boundary and the "earliest" boundary cannot be separated.
- The additional-checkpoint effect is at the level of per-cell noise.
- The sample is small: 12 tasks, 3 repositories, one tier, one agent, one model version.
- No learned predictor and no matched-budget study.
- K = 1 failure per candidate, and only fail-stop failures (no semantic corruption, no irreversible side effects).

**Mine**
- **No seed control.** Without it, "paired" branches are not paired in the sampling sense, and 2 to 3 repetitions are thin
  when noise/signal is 1.04 in the additional stratum.
- **The restore method may explain part of the finding.** The restored context is a reconstructed transcript plus
  undefined "discovered facts". A restored Codex session is not shown to be the same model context as the original. So
  "re-derivation" may partly reflect how state was restored, not only agent behaviour. This is not tested.
- **"Agent importance" is undefined.** The paper never says how it was elicited or on what scale. That weakens the one
  data point that touches C5.
- **Two different creation costs.** 4.41 s appears in Sec 4, Sec 6, App E and G.8; 4.38 s appears in App A and App F. The
  two are not reconciled.
- **Unrelated self-citations.** App A ("Trustworthy and adaptive foundation-model systems") cites nine of the authors'
  unrelated papers (unlearning, fairness, audio explainability, membership inference) inside the protocol section.

## Assumptions the paper does not test

- That restoring the transcript recreates the agent's effective state, i.e. that a restored agent continues the way the
  original would.
- That a fail-stop at the next logical step is representative of real failures.
- That branches which both pass the verifier produced comparable fixes. Patch identity across branches is not reported.
- That the result transfers to smaller, open or lower-effort models.

## What it does NOT do that the idea needs

1. Vary what is in context at a fixed state: the graph pushed into context versus pulled by tools, or a true versus a
   decoy edge. Its treatment is which saved state is restored.
2. Hold the sampling seed fixed across arms. Its runtime cannot do this.
3. Measure where the agent goes next (files or functions read or edited). Its outcome is the cost to finish.
4. Use code-graph tools, a small open model, or a context budget.
5. Score "following" against a base rate.

**Worth borrowing**
- **Fork-vs-fork pairing.** Both arms are re-sampled from a restored state, rather than compared against the original
  run.
- **Rigour devices:** randomized branch order, a predeclared repetition rule for sign-unstable cells, and a task-level
  bootstrap.
- **Its cost ledger:** about 10 s per restore and about 14 MB per archive for SWE-bench Verified workspaces.
- **Its noise figures** argue for seed control. An open model under our own harness gives us that; Codex did not give
  them.

**Lead (abstract read through the arXiv API, paper not read).** Causal Agent Replay (Shah 2026, arXiv 2606.08275). Sec 5
cites it as sharing the same instrumentation problem.
- It models an agent run as a structural causal model, applies a do-operation to one step, and re-executes forward under
  the same stochastic policy.
- It uses a point-of-commitment rule for the confound that stochastic re-execution creates, plus a Monte-Carlo Shapley
  estimator.
- **Read it in full before claiming observation-level forks as ours:** we need to check whether its intervention algebra
  covers replacing an observation's content (C4).
