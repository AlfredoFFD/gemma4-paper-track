## Claim (key numbers and where they are)

Agents adopt plausible but corrupted tool returns at high rates, across three tools and 14 models.
- **Adoption (Table 1, Section 4.1).** Mean P1 adoption is 68.0% for Search [95% CI 65.3, 70.7], 40.1% for Sub-Agent [31.9, 48.5] and 35.5% for Code Executor [32.3, 39.0].
- **Override (Table 1).** Corrupted returns override answers the model gives correctly without tools: P1 override rate 56.4% / 26.8% / 33.5%.
- **Persistence (Table 2, Section 4.3).** Adoption persists in harder tasks (QuALITY adoption 94.7%, override 91.9%) and in two-tool tasks, where accuracy falls from 98.4-98.8% to 19.8-26.2% when both returns are corrupted.
- **Delivery depends on the tool (Table 3, Section 4.4).** Pushing the same content into the prompt instead of returning it from a tool raises Search adoption under the RAG header and leaves Sub-Agent unchanged. It cuts Code Executor adoption from 40.2% to 1.8-3.8%.
- **Doubt without action (Section 4.5, Figure 3, Table 4).**
  - Agents make more calls under corruption, and reasoning traces state the conflict: Qwen thinking models flag one in 87.9-96.0% of adopting Code runs and state the correct value in 64.2-73.0%.
  - Yet final answers warn the user only 4.2% of the time (1.5% without Muse).
- **Mitigations (Section 5; Tables 5, 6, 7, 28, 30, 31; Figure 4).**
  - Verify prompts are the best balance: pooled ΔP1 of -4.0 / -4.0 / -9.8 pp with P0 accuracy kept.
  - A "Low" reliability label gives -4.0 pp.
  - SFT, DPO, GRPO and OPD give limited or negative gains.
  - Activation steering helps only some models, depending on strength.

## Method (enough to reproduce)

**Metrics (Section 3).**
- **Adoption rate** = runs whose final answer uses the injected content / runs in which the injected content actually appeared in a tool response.
  - For Search, exposure requires a delivered, parsed payload containing the assigned value through a successful edit.
  - A tool call alone does not count as exposure (Appendix F.2).
- **Override rate** = adoption rate restricted to items the model answers correctly without a tool in at least 2 of 3 independent no-tool runs.
- **Base accuracy** = accuracy over the individual no-tool responses.

**Search (Section 3, Appendix A).**
- **Data.** 418 FreshQA questions from the 21 Apr 2026 snapshot (432 minus 14 binary ones): 147 never-, 127 slow- and 144 fast-changing. The system-prompt date and the search end date are fixed to the snapshot.
- **Search calls.** Agents issue their own Tavily queries (topic=general, depth basic, max_results=10, answer synthesis off); the top 5 results are kept, with title, url, content and score fields.
- **Corruption levels.** Each question has one fixed alternative answer per level, shared across models and repetitions:
  - P1 plausible: a once-true or confusable value, e.g. the former chancellor.
  - P2 transplanted: the gold answer of another FreshQA question.
  - P3 nonexistent: an invented entity, or an extreme numeric or date value.
- **Rewriting.** GPT-5.6-Luna rewrites the answer-relevant titles and content to assert the alternative.
  - If no result carries an answer claim, the value is inserted into the most relevant result.
  - Gold aliases are scrubbed from URLs and text, and results that still carry a gold alias are excluded.
  - So every return the agent can get asserts the corrupted value; there is no way to search for counterevidence.
- **Caching.** Identical normalized queries get identical cached returns across models and repetitions.
- **Run limits.** 10-turn cap, then one tool-free final-answer turn; 200k-token total budget; 8k output (24k for reasoning models).
- **Judge.** Qwen3.5-27B (thinking off) labels each answer CORRECT / ADOPT / BLEND / OTHER / ABSTAIN, plus a warning flag. Only ADOPT counts.
  - Human check on 200 stratified runs: Fleiss κ=0.857 among humans; judge agreement 98.5% (Cohen κ=0.940), precision 28/28, recall 28/31.

**Sub-Agent (Section 3, Appendix B).**
- **Corpus.** 45 documents, three per field from five fields (AI, medicine, physics, psychology, economics) in each paper group:
  - 15 pre-cutoff papers
  - 15 post-cutoff papers (released after 1 May 2026)
  - 15 pieces of 19th-century fiction from Project Gutenberg
- **Task.** The user asks for summaries of three titles from one group. A `subagent` tool returns a stored five-sentence summary (90-160 words) per document; repeated calls return identical text.
- **Corruption.** GPT-5.6-Terra drafts:
  - P0: a correct summary
  - P1: one headline claim replaced with a false claim
  - P2: one false claim added
  - All are reviewed by the authors and checked mechanically (one edit; content-word retention ≥0.85 for P1 and ≥0.92 for P2).
- **Runs.** 16k output, 50 turns, temperature 0.7, no API seed. 180 three-document requests × P0/P1/P2 × 3 repetitions per model, for 22,680 requests and 68,040 document judgments in total.
- **Judge.** Qwen3.5-27B with three calls: locate the slot, probe the claims, break ties.
  - Human check: 155 items, of which 126 have a majority; agreement 94.4% (κ=0.841), precision 25/27, recall 25/30.

**Code Executor (Section 3, Appendix C).**
- **Problems.** 300 arithmetic problems, 50 each of +, ×, ÷, mod, log and power, with gold answers from 50-digit arithmetic rounded to 3 decimals.
- **Corruption.** `python_executor` runs the agent's code. On success, every numeric token in stdout is replaced by o' = s·o·r (d=+1) or s·o/r (d=-1), with r = 1 + p/100.
  - p is log-uniform on [1, 100] for P1 and [101, 10000] for P2.
  - The direction-sign pairs (d, s) are balanced, 75 problems each.
  - The corruption factor is fixed per problem across calls. Tracebacks pass through uncorrupted.
- **Runs.** 3 repetitions, at most 50 tool calls, 16k output.
- **Grading.** A rule-based grader matches within 5e-4. Adoption = the answer matches the injected value or any other corrupted number returned. Parse failures count as non-adoption (237 parse failures and 26 API errors across P1 and P2).

**Models (Table 8).**
- Qwen3-30B and -235B, each as instruct and thinking variants (OpenRouter, fp8).
- Gemini-3.1-flash-lite and 3.7-flash.
- GPT-5.4-mini and -nano.
- Gemma-4-12B and -31B (local vLLM, bf16).
- GPT-OSS-20B and -120B (MXFP4).
- DeepSeek-V4-Flash (fp8).
- Muse-Glimmer-30B (bf16).
- Decoding T=0.7 (reasoning effort medium where applicable); API seed 12345 plus the repetition offset where supported.

**Extensions (Section 4.3, Appendices D.3-D.5).**
- **MuSiQue:** 60 multi-hop questions, 3 models, 1 run.
- **QuALITY:** 60 four-choice Gutenberg questions; the sub-agent returns a fixed 8-10 sentence report in which one decisive sentence supports a distractor; 7 models × 3 runs.
- **Two-tool tasks:** 54 tasks, a fact tool plus a code tool, 6 models.
- **GSM-Hard:** 871 problems, 7 models.
- **Frontier models:** GPT-5.4, Claude Sonnet 5, Claude Opus 4.8 and Grok 4.6 on a prespecified 90-item Search subset, one no-tool run and one P1 run each.

**Presentation (Section 4.4, Appendix F.1).** The same P1 content is delivered three ways:
- **Tool:** the main-evaluation runs, with the agent's own queries, tool access and 3 repetitions.
- **User:** the payload is pasted into the user turn after "Here's what I found online:" (Search), "I had someone look into these" (Sub-Agent), or as the number stated directly (Code).
- **RAG:** the payload sits under a `Context:` header.

The User and RAG arms use the no-tool system message, one response per item, and for Search a frozen 5-result payload generated from the canonical question. They differ from Tool in tool access, query provenance, interaction structure and repetitions as well as in presentation, which the paper acknowledges.

**Interventions (Section 5, Appendices F-H).**
- **Prompt policies:** Compare (check against prior knowledge and constraints), Verify (on conflict, run one substantively different follow-up check), Disclose (state the competing claims to the user). Six models, one repetition each.
- **Search metadata:** source labels (Wikipedia, Reuters, Reddit, X) and reliability labels (0.10/0.50/0.95, Low/High), each with an instruction to consider the label; a passive variant has no instruction.
- **Post-training:** LoRA r=32 / α=64 on the attention projections, on a PopQA+Wikidata/TempLAMA/TimeQA search pool with synthetic returns:
  - SFT: 194 clean trajectories
  - SFT (recovery): plus 64 resisting trajectories
  - DPO: 327 pairs sharing a prefix through the corrupted return, β=0.1
  - GRPO: 452 questions with a clean and a corrupted fixed prefix, 1 epoch, 226 steps, judge-assisted correctness reward
  - OPD on Gemma-4-12B with 10%, 25% or 80% corrupted contexts
- **Probes:** logistic regression (C=0.05, 5-fold grouped by problem) on residual activations at the last prompt token after the first tool return.
- **Steering:** a corrupted-minus-correct mean-difference direction over 3-layer bands, applied from the first tool return onward. 200 problems to estimate it and 100 held out, greedy decoding, ≤4 tool rounds, 300 tokens per turn.

**Statistics (Appendix E).**
- Item-bootstrap CIs (2,000 resamples for the main evaluation).
- Paired within-item contrasts with sign-flip permutation tests and Holm adjustment for the presentation, prompt and metadata families.
- Post-training intervals are unadjusted.

## Setting, data, models

Factual QA with web search, document summarization with a sub-agent, and arithmetic with a code executor, across 14 open and closed models, including Gemma-4-31B and Gemma-4-12B. The agents are multi-turn tool loops with large budgets.

There is no coding agent, no repository, no code graph, no quantization below bf16 for Gemma, and no tight context limit.

## Limitations: the authors'

- **Reproducibility.** API models may change or be retired, outputs are stochastic, and search results drift. Fixed targets, cached summaries, 3 repetitions and item-bootstrap CIs mitigate this but do not remove it (Reproducibility statement).
- **Presentation confound.** The presentation conditions "vary in tool access and interaction structure as well as presentation" (Section 4.4).
- **Conditional on exposure.** Metadata and prompt contrasts describe adoption conditional on exposure, not effects over all scheduled episodes (Appendices F.2-F.3).
- **Post-training intervals.** They cover question resampling only, not run or harness variance. The Qwen GRPO comparison is descriptive because its context-handling settings differed (Appendix F.4).
- **Probe vs steering.** Probe AUROC does not establish that the steering layers are optimal (Appendix G.2).
- **Scale.** Post-training conclusions hold "at the scales tested" (Section 5.3).

## Limitations: mine

1. **The Search environment is adversarially consistent.** Every return for an item asserts the decoy, and gold aliases are scrubbed. The agent cannot recover by searching, so Verify can only work through parametric memory. Real tool unreliability usually leaves some disagreeing evidence. Adoption here is an upper-end estimate for retrieval.
2. **Push vs pull is confounded four ways.** Tool access, query provenance (agent-written vs canonical), repetitions (3 vs 1) and denominators all differ between the arms. The Search effect, and the reversal for Code (an asserted number vs the output of code the agent wrote itself), cannot be attributed to visibility alone.
3. **Exposure-conditioned rates can hide selection.** Interventions change who gets exposed (Qwen3-30B under Compare: 204 eligible vs 1,133). OPD checkpoints are exposed 2-4x less. Adoption among the exposed can rise while total harm falls.
4. **The probe may read the input, not a belief.** At AUROC ≈1.0, the probe may detect the input mismatch (stdout numbers that do not match the code) rather than a belief the model holds. Steering on Gemma does not move adoption, so separability is not shown to be behaviorally usable.
5. **The conflict statistics are loose.** The label includes rounding and format remarks, precision is 0.844, and GPT and Gemini expose only summaries. Several cells rest on 3-43 readable runs.
6. **No base rate for the decoy under true returns is reported.** From P0 accuracy one can bound it: Search 94.2% means the injected value is output in at most 5.8% of P0 runs (six models); Code ≤0.2% (my arithmetic). The paper itself only uses no-tool correctness (override) as the control.
7. **Item-level effects are small next to model heterogeneity.** Most pooled intervention effects are 1-10 pp, while per-model effects range from about +17 to -59 pp (Tables 27 and 29).
8. **Gemma ran in bf16.** No 4-bit and no long-context pressure: budgets are 10-50 turns with 16k-24k outputs and 200k tokens.

## Assumptions the paper does not test

- That adoption conditional on exposure is comparable across conditions with very different exposure rates.
- That the Tool vs User/RAG difference is about presentation rather than tool access or self-generated queries.
- That fully consistent corruption generalizes to mixed, partly correct tool returns. P1-mix exists only in GRPO training data.
- That the results transfer to tools whose outputs guide what the agent does next (navigation and edits) rather than supply the final answer.
- That reasoning-trace statements reflect the computation that drives the answer.
- That results hold under quantization or tight context.

| C1 Setting | partly | Multi-turn tool-using agents, including Gemma-4-31B and -12B (bf16, local vLLM; Table 8), with search, sub-agent and code executor (Section 3). ## What it does NOT do that the idea needs

- **No software engineering.** No code graph, no repository, no end-to-end bug repair, and no measure of where the agent reads or edits next. The outcome is always the final answer.
- **No clean delivery comparison.** No push vs pull comparison from an identical agent state. The paper's own comparison differs in tool access, queries and repetitions, so it cannot attribute effects to visibility.
- **No base-rate-scored decoy.** No planted wrong-but-plausible structural relation scored against how often the agent goes to the same target when the information is true.
- **No forks.** No paired counterfactual forks with a shared prefix and seed, and no short-continuation measures.
- **A different regime.** No 4-bit Gemma and no 16k context regime.
- **No presentation variants of structural information** (bare names vs names + signature + file:line).
- **No market agents.**

What it gives the idea:
- **A Gemma-4-31B prior for the C2 direction in retrieval.** Pushing the same content into the prompt raises adoption by about 17-19 pp. This is the number a judge may cite against an unqualified "push beats pull" claim; it is also a model-matched prior.
- **A reversal to address.** For outputs of code the agent ran itself, pull beats push by about 36-38 pp pooled. The idea's C5 claim needs to say why graph structure behaves like retrieved content and not like self-computed output, or test both.
- **Evidence that cheap mitigations will not work on our model.** No prompt policy lowers Gemma-4-31B adoption in any tool (Table 29).
- **Strong citable evidence that calls, stated doubts and internal separability do not imply non-adoption.**
