# Agents Explore but Agents Ignore: LLMs Lack Environmental Curiosity

- **arXiv:** 2604.17609 (cs.CL), v1, 19 Apr 2026, CC BY 4.0, marked "Preprint. Under review."
- **Authors:** Leon Engländer, Sophia Althammer, Ahmet Üstün, Tom Sherborne (Cohere); Matthias Gallé (Poolside)
- **Version read:** v1, arXiv HTML full text (`private/lit/2026-10-27/fulltext/2604.17609.txt`). All figure and table pages of the 24-page PDF were viewed; Figs. 1–5 and 8 were re-rendered at 5–6× to read the point labels. Read 2026-10-27.
- **Leaned-on references, looked up:**
  - Terminal-Bench, Merrill et al. 2026 = arXiv 2601.11868. The paper uses v1, with 80 tasks (App. D).
  - SWE-agent (Yang et al. 2024) and AppWorld (Trivedi et al. 2024) are the standard benchmark and scaffold papers.

**One-line verdict:** this is the closest published evidence, in coding agents, for the C5 half "found ≠ used".
- Agents bring an injected gold solution into their own context through their own tool calls in 53–100% of runs, but touch it in only 0.3–50%.
- Putting the same content in the task prompt lifts pass@1 from 55.88 to 76.25 (App. A.2).
- C1 partly: large open models, no graph, no context cap.
- C2 partly: one unpaired discover-vs-push comparison, plus file-name and format variants.
- C3 only nominally: Level-5 decoy files exist, but following them is not measured.
- C4 and C6: not covered.

## Claim

- **H1, agents lack "environmental curiosity"** (§3.1, Fig. 2). They discover injected solutions but rarely interact with them (discovery@1 vs interaction@1):

  | Benchmark | Discovery@1 | Interaction@1 |
  |---|---|---|
  | Terminal-Bench (TB) | 78.6–81.2% | 37.1–50.3% |
  | SWE-Bench Verified | 53.4–98.2% | 5.9–17.4% |
  | AppWorld | > 90% | ≤ 6.3% |

  On AppWorld, gpt-oss-120b discovers the solution API in 97.54% of runs and calls it in 0.53% (Fig. 1).
- **H2, test-time factors modulate but do not close the gap** (§3.2):
  - Removing str_replace_editor (bash-only) raises interaction given discovery.
  - Higher reasoning effort raises it: on TB, P(interaction | discovery) goes 17.65% → 36.68% → 45.69% for low/medium/high.
  - Exploration prompts raise both interaction and pass@1.
  - Even with all of these optimised, agents ignore the solution in most runs.
- **H3, narrow in-distribution SFT lowers interaction and pass@k scaling** (§3.3, Tables 2–3, Fig. 5).
- **Ignoring is passive, and the ability exists** (§4, App. A):
  - An LLM judge finds 0% "suspected trap" and 50–99.6% "no acknowledgment" of the solution.
  - Pushing the solution into the prompt gives 76.25 pass@1.
- **Outcome metrics like pass@k cannot separate adaptive agents from fixed-pattern agents,** so the paper argues for process metrics (interaction@k) (§4).

## Method (enough to reproduce)

1. **Solution injection** (§2.1). The gold solution is placed in the environment so that it is complete and discoverable.
   - TB and SWE-Bench Verified: an executable `solution.sh` in the agent's working directory (for SWE, `/testbed`).
   - AppWorld: a `solution` endpoint listed in `cli --help`. It is one line among the apps, with the description "Display the solution for the current task" (Fig. 1).
   - AppWorld uses the validation (dev) split, because gold solutions exist only there.
2. **Agent stack** (§3, App. E).
   - Harness: Docker environment plus grading.
   - Scaffold: a ReAct loop, either Terminus 1 (default) or SWE-agent. Both are adapted to native function calling.
   - Tools: bash only, or bash + str_replace_editor. For SWE-agent, "bash-only" means bash plus submit.
   - Terminus exposes one `terminal_use` tool. It sends tmux keystrokes with waits and returns a pane capture with "in_progress" and "truncated" flags.
   - Not stated: max turns, token budgets, truncation limits.
3. **System prompts** (Figs. 10–12).
   - TB: adds an Exploration section and orders the agent to investigate every discovered file before the main task. This is the best prompt from B.4.1 and the default for all TB runs.
   - AppWorld: orders the agent to call `cli --help` before attempting the task.
   - SWE-Bench: SWE-agent-style steps (find relevant code, reproduce, edit, rerun, edge cases), with no exploration or investigate instruction.
4. **Models.**
   - gpt-oss-120b (117B total / 5.1B active MoE) at high reasoning by default, plus medium and low.
   - GLM-4.5 and GLM-4.7 (355B / 32B active MoE).
   - Fine-tunes of command-a-reasoning (111B dense).
   - n = 10 attempts per task. Task counts are stated only for TB v1 (80).
5. **SFT** (§3.3, App. C).
   - Base: a variant of command-a-reasoning already SFT'd for instruction following.
   - Rejection sampling: 5 trajectories per training task from gpt-oss-120b (high) in Terminus 1; keep the shortest successful one.
   - Three task distributions:

     | Model | Training data | Turns × epochs |
     |---|---|---|
     | T-Bench-SFT | TB-like tasks from a vendor | 14,005 × 2 |
     | AppWorld-SFT | AppWorld train split | 15,841 × 2 |
     | SWE-Bench-SFT | SWE-smith | 21,424 × 1.5 |

   - About 30k effective task turns each, mixed 1:1 with a general tool-use SFT set. That set alone scores 5.12 pass@1 on TB and 0.18 on AppWorld.
   - Seeds: 3 for T-Bench-SFT and AppWorld-SFT; 1 for SWE-Bench-SFT.
6. **Analyses:**
   - scaffold × tools on SWE-Bench (Fig. 3, Table 8)
   - reasoning effort (Fig. 4)
   - prompt variants (Tables 11–12, Fig. 9)
   - file names (Table 9)
   - five difficulty levels (Table 10)
   - temperature 0–1 (Fig. 8)
   - reasoning history kept vs dropped (A.3)
   - an LLM judge of discovered-but-ignored runs (A.1)
   - oracle push interventions (A.2)
7. **Judge** (A.1, Fig. 6).
   - GLM-4.7 is forced to call a tool with one of 5 categories plus an evidence quote. The categories:
     1. no acknowledgment
     2. acknowledgment without investigation
     3. deliberate rejection as a trap
     4. deliberate rejection to prefer its own approach
     5. interaction planned but not executed
   - Input: each discovery turn plus the agent's reasoning and actions for the next 3 turns.
   - Separate system prompts for the file variant and the API variant.
   - 50 random classifications were checked by hand; the evidence quotes were correct in all of them.
8. **Oracle interventions** (A.2, Table 5; gpt-oss-120b high, TB):
   1. baseline (`solution.sh` present)
   2. a user message injected at first discovery, asking whether any observation is relevant
   3. the full solution injected as the agent's first reasoning step (unmodified TB, no file)
   4. the full solution in the task prompt (unmodified TB)
   5. the task prompt tells the agent to find and execute `solution.sh`

## Setting, data, models

- **Benchmarks:**
  - Terminal-Bench v1 (80 terminal tasks)
  - SWE-Bench Verified: end-to-end GitHub issue repair by editing repository code, which is the coding setting
  - AppWorld dev split: everyday tasks done by calling app APIs through a CLI
- **Models:** gpt-oss-120b, GLM-4.5, GLM-4.7, command-a-reasoning SFT variants. All open-weight and large. None is small, quantised, or run under a hard context cap.
- **Turns on successful trajectories** (gpt-oss high): TB 26.2, AppWorld 29.6, SWE-Bench 62.8 (App. D).
- **Absent:** code-graph or other structural tools. Tools are bash and str_replace_editor only.

## Metric (exact definitions)

- **pass@k, discovery@k, interaction@k** use the unbiased estimator of Chen et al. 2021, over n = 10 attempts per task, averaged over tasks:
  - metric@k = E_tasks[1 − C(n−c, k) / C(n, k)]
  - c is the number of attempts that pass, discover, or interact.
- **Discovery:** the attempt runs a command that surfaces the injected solution in the agent's context. Examples: `ls` listing `solution.sh`, or `cli --help` listing `solution`.
- **Interaction:** any executed command references the solution as a string, e.g. contains "solution.sh" or "cli solution". Reading and executing count the same.
- **P(interaction | discovery):** used in Fig. 3 and §3.2, but the exact computation is not given. My ratio int@1 / disc@1 from Table 8 reproduces most of the plotted values, but not all (see Fig. 3).

## Limitations

**The authors' own:** there is no limitations section. Scattered statements:
- solution injection is a deliberately trivial first step, and richer measures are needed (§4, B.3)
- measuring curiosity in base models is an open problem (§4)
- AppWorld runs use the validation split (§3)
- Table 3's SWE results come from a single seed

**Mine:**
1. **No uncertainty anywhere.** No CIs and no tests, with n = 10 attempts per task. Several reported contrasts are a few points or less (Table 3 pass@1; prompt variants).
2. **Prompts confound the cross-benchmark comparison.**
   - The TB prompt orders the agent to investigate every discovered file; with the base prompt, TB int@1 is 23.12 (Table 12).
   - The AppWorld prompt forces `cli --help`.
   - The SWE prompt has neither.
   - So "TB 37–50% vs SWE 6–17%" mixes the benchmark with the prompt.
3. **Discovery is lenient.** A filename in `ls` output, or one line in a help list, counts as discovered, which is not the same as attended. On SWE, 96.8–98.5% of discovered-but-ignored runs have no acknowledgment. That fits "never processed" as well as "ignored".
4. **Interaction is a string match.**
   - It counts commands like `ls solution.sh`.
   - It misses `cat *`, globs, or reading through a script.
   - It never checks whether the content was used.
5. **The judge has weaknesses.**
   - GLM-4.7 grades runs that include its own (half of Table 4).
   - It sees only 3 turns after discovery.
   - The 50-case manual check verified evidence quotes, not agreement on categories.
6. **The push conditions are unpaired and confounded.** A.2 conditions 3 and 4 run on unmodified TB with no file, while the baseline has the file. There are no paired forks, one model, and no CIs.
7. **The gold solution does not guarantee success.** At 95% interaction, pass@1 is 81.67 (Table 5), contradicting the "complete solution guarantees success" requirement in §2.1. Pass@1 gains therefore understate use.
8. **"Tool-use habits originate from pre-training" is not tested** (§3.2). The base model is post-trained and tool-using, and a general tool-use SFT set was mixed in 1:1.
9. **Internal inconsistencies,** listed above: Fig. 3 vs Table 8; Tables 2, 3 and 6; 29.8 vs 26.9; the Fig. 9 prompt; the abstract's wording vs Fig. 1.
10. **"Bash-only roughly doubles interaction"** holds in 2 of 4 configurations (the range is 1.13–2.06×).

## Assumptions the paper does not test

- That naming the file in a command is the behaviour that matters, and that pass@1 gains come from it. Table 1 is only correlational.
- That a gold-solution file is "unexpected but relevant" in the same way ordinary environment information is. The paper assumes, without showing it, that the result carries over to subtler or solicited information, such as the results of the agent's own targeted queries (§2.1).
- That agents do not avoid "solution" artifacts because of learned anti-shortcut norms. The judge only sees verbalised reasoning over 3 turns.
- That pushed vs discovered differ only in placement, not in format: the full content is pushed, while only a filename or one help line is discovered.
- That conclusions hold when the injected information is wrong. Every main condition injects a true solution, and the Level-5 decoys are not analysed for following.

## C5 focus: how the gap between finding and doing is measured

- **The gap:** discovery@k minus interaction@k, and P(interaction | discovery), measured per attempt.
  - "Sees" means the solution's name is surfaced in a tool observation by the agent's own command.
  - "Does" means a later command names the solution.
- **Reasoning-level check:** the judge's categories over the 3 turns after each discovery. No acknowledgment ranges from 50.0% (gpt-oss, TB) to 99.6% (GLM-4.7, AppWorld). Active rejection as a trap is 0% everywhere.
- **Ability check:** pushing the content raises pass@1 (Table 5):
  - into the task prompt: 76.25
  - into the first thought: 61.67
  - vs 55.88 with only the discoverable file, and 44.50 with no solution
  - A generic "reflect on your observations" message at discovery raises int@1 from 37.12 to 53.33.
- **Environments:**
  - Terminal-Bench v1: terminal tasks
  - SWE-Bench Verified: end-to-end repair, the coding case
  - AppWorld: API chores done through a CLI
- **Models:** gpt-oss-120b (low / medium / high), GLM-4.5, GLM-4.7, command-a-reasoning SFT variants. No small model, no context cap.

## What it does NOT do that the idea needs

- Solicited pull: graph structure returned by the agent's own targeted queries. Their discovery is incidental, inside generic listings.
- Paired counterfactual forks from one saved state with a shared seed, and McNemar-type paired outcomes.
- A planted false structural relation, with following measured against the base rate for the same target when the information is true.
- A small quantised model under a hard context budget, and counts of interface failures (edit mismatches, overflow, malformed patches).
- Measuring where the agent reads or edits next after delivery. They only string-match commands and score pass@k.
- Any graph or structural representation of code.

**Useful for us:**
- **Estimators:** the discovery@k and interaction@k estimators.
- **Hold the tool set fixed.** Adding str_replace_editor lowered inspection in every configuration, so the tool set must be identical across delivery arms.
- **Hold the prompt fixed.** Prompt wording alone moved TB int@1 from 23.12 to 37.12, so prompts must be identical across arms.
- **Seeds matter.** Runs vary even at temperature 0, so forks need fixed seeds and logged nondeterminism.
- **Decoys can hurt.** A costly, decoy-like artifact (L4) pushed pass@1 below the no-injection baseline (37.92 vs 44.50).
- **Where to differentiate.** Their gap concerns unexpected information. Our claim should be framed as being about expected, queried structure vs pushed structure, and about following it when false. This paper covers neither.
