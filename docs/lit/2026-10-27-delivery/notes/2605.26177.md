# RepoMirage: Probing Repository Context Reasoning in Code Agents with Perturbations

- **arXiv:** 2605.26177 (v1, 25 May 2026, cs.SE, CC BY-SA 4.0). Checked with `lit.py verify` (title match 1.0, authors OK).
- **Authors:** Hanyu Li and Yichi Zhang (equal contribution), Speed Zhu, Hang Su, Jun Zhu, Yinpeng Dong (Beijing University of Posts and Telecommunications; Tsinghua University; Tencent).
- **Version read:** v1. The arXiv HTML full text (1030 lines) and the 22-page PDF, read on 2026-10-27.
- **Leaned-on references, looked up:**
  - "The SWE-Bench Illusion" (arXiv:2506.12286): models find buggy file paths without the repository structure.
  - PatchRecall (arXiv:2604.10481): over 80% of SWE-Bench Verified fixes edit one file.
- **One-line verdict:** This is the closest of the two papers in setting. It runs end-to-end repair on SWE-Bench Verified with mini-swe-agent. It plants decoy files next to the real target, which is the most damaging of its perturbations. And it shows that pushing structural knowledge into the prompt raises success a lot. But it has no code graph and no pull-vs-push contrast with the same information. It never measures how often the agent follows the decoy against a base rate, it has no forks, and it uses frontier models with no context limit. It partly covers C1, C2, C3 and C5, and does not cover C4 or C6.

## Claim

- **Issue-resolution scores overstate "repository context reasoning".** Under three perturbations that keep the program's behavior, across 8 models (Sec. 3.2; Table 1):
  - the mean resolved rate drops from **66.80% to 49.78%**;
  - the mean number of files accessed rises from 4.77 to 13.24.
- **The quoted relative drop does not quite match the table.** The intro says resolved rates "drop relatively by 27.0% on average". Re-derived from Table 1 it is 27.24% (mean of the per-model relative drops) or 25.49% (drop of the means).
- **Perturbation-derived tasks are much harder.** On the same instances, mean success on the "RepoMirage-Extend" tasks is **25.25%**, against 66.80% for the original issue resolution (Sec. 4.2; Table 2).
- **"Exploration drift"** (Figs. 5, 11, 12): agents open more files but stay in exploration instead of moving to edits.
- **Two "push" interventions help.**
  - A generic structural-hint prompt raises Extend success: GPT-5 27.60 → 62.60, DeepSeek-V3.2 39.80 → 76.80 (Table 3).
  - "RepoAnchor" runs in two stages: explore and write INSTRUCTION.md, then solve. It raises average Extend success by +7.2 to +17.0 points for four models (Fig. 7).

## Method (enough to reproduce)

**Perturbations** (Sec. 3.1; App. A.4; implemented with LibCST syntax-tree transforms).

1. **Dependency-path indirection.** Each direct import in a target file is rerouted through a four-layer proxy chain.
   - Only absolute imports that do not depend on the repository layout are rerouted, **e.g. `json` and `re`** (App. A.4; Fig. 1).
   - Proxy files are named `proxy_*` (Fig. 8). Fig. 13 shows `from proxy_4n108 import dep_ko4r22 as _lll_reit`.
2. **Runtime-target masking.**
   - The target file is renamed to a random name (e.g. `forms.py` → `flux_cinder_hh.py`; Fig. 13).
   - A same-named package directory is created. Its `__init__.py` loads the renamed file by explicit path, using `spec_from_file_location` and `exec_module`.
   - Nearby **decoy files** are added. They are "globally similar to the target but contain locally perturbed details": a reversed boolean condition, shuffled import aliases, or a mismatched dependency key.
   - Decoys are never imported or executed (Sec. 3.1; App. A.4–A.5).
3. **Local-value externalization.** Local constants move into external JSON files named `dependency_*`, three values per file. The code loads and merges them at runtime (App. A.4; Fig. 8).

**Validation.**
- The official PASS_TO_PASS tests are run on the perturbed repository.
- The gold patch is applied to the original repository, the perturbations are applied on top, and FAIL_TO_PASS is run (App. A.4).

**Extend tasks** (Sec. 4.1; App. A.5).
- All of them run on fully perturbed repositories.
- Each instance goes to exactly one task family, chosen by its "most salient structural signal", with the families kept roughly balanced (Fig. 4).
- The prompt lists the files the agent may modify. The checkers reject edits to any other file.

| Family | Instances | What the agent must do | How it is checked |
|---|---|---|---|
| Multi-File Issue Resolution | 70 | Fix an issue whose gold patch spans several files | Official tests |
| Proxy Chain Completion | 144 | Restore an erased middle proxy file | Checker imports the aliases and compares the modules they resolve to |
| Runtime Target Identification | 142 | Edit only the wrapper `__init__.py` so it loads the real file, not a decoy (the wrapper's reference to the real file has been removed) | Checker verifies the real file is loaded |
| Missing-Constant Recovery | 144 | Restore erased keys in the JSON files | Checker merges the files and compares key-value pairs |

**Agent** (App. A.2).
- mini-swe-agent, bash-only, at most 250 steps.
- Default temperature, top-p and maximum generation length.
- Prompt, environment and stopping criteria are identical across models.

**Trajectory metrics** (App. A.6).
- Shell commands are classified by rules into edit, test, search and read. Search and read are merged into "explore".
- Transition probability: p_{a→b} = #(a→b) / Σ_s #(a→s), computed per trajectory and aggregated.
- A file counts as **accessed** only if its contents were exposed to the agent; being listed is not enough. Files are deduplicated.
- **Explore-stage proportion** = the share of steps before the first edit.

**Structural hints** (Sec. 5.2; App. A.7; Fig. 8).
- One fixed template is prepended to the task. It is identical across instances; only the problem statement changes.
- It says the repository "has been intentionally perturbed" and describes:
  - renamed files;
  - **decoy files**;
  - `proxy_` files forming a "four-layer import graph";
  - `dependency_` JSON files;
  - wrapper folders.
- It does not name the files for any specific instance.

**RepoAnchor** (Sec. 5.3; App. A.8; Figs. 6, 9, 10).
- **Stage 1.** The agent is told not to solve the task or edit anything. It must:
  - locate the relevant directories, explore them and infer each file's role;
  - check its picture with runtime commands;
  - "do not trust the filename or the other surface patterns";
  - write `/testbed/INSTRUCTION.md` with fixed sections: files read with who uses whom and the runtime evidence, the detailed structure, and unclear points.
- **Stage 2.** The agent gets the original prompt plus a guide.
  - The guide says a colleague wrote INSTRUCTION.md. The agent has to read it from disk itself.
  - It should be used "reasonably", and "the content here may be wrong".

## Setting, data, models

- **Seed benchmark:** SWE-Bench Verified, 500 instances. The paper never states n, but it is implied:
  - every resolved rate is a multiple of 0.2;
  - the Fig. 4 counts sum to 70 + 144 + 142 + 144 = 500;
  - the Fig. 2 counts of 325 and 350 resolved match 65.0% and 70.0% of 500.
- **Models (8):** GPT-4.1, GPT-5, Gemini-3.1-Pro, Claude-Sonnet-4.6, DeepSeek-V3.2, MiniMax-M2.7, Qwen3-Coder-Next and Qwen3.6-35B-A3B.
  - Proprietary models are called through their APIs.
  - The two Qwen models run on vLLM on 4×A800-80GB (App. A.1, A.3).
  - The analysis uses mostly GPT-5 and DeepSeek-V3.2.
- **Environment:** Docker SWE-Bench images on Ubuntu 20.04. Python repositories only.
- **Runs:** as far as the paper says, one run per model, instance and condition. No seeds, repeats or confidence intervals are reported.

## Metrics

- **Resolved %:** passes the official SWE-Bench tests (issue resolution). For the Extend tasks it is the checker pass %.
- **Avg. #Files:** distinct files whose contents were exposed to the agent (App. A.6).
- **Behavior metrics:** explore-stage proportion and transition probabilities.
  - Δ is the per-instance change from SWE-Bench Verified to the perturbed or Extend condition (Figs. 5, 11, 12).
  - Stars mark significance, but **the test is never named**.

## Limitations

### The authors'

- Python repositories only, and the classic "modify the repository to meet a goal" task format (App. C.1).
- Misuse risk (App. C.2).

### Ours

1. **The headline mixes a change of task with a change of capability.** Extend vs "Org." compares different tasks, e.g. "restore an erased proxy file for `json`" vs "fix the issue". So the 66.8 → 25.3 headline mixes task difficulty with capability. Only Multi-File is a like-for-like comparison (34.82 → 17.86 on average).
2. **The perturbed "dependencies" are not the project's own structure.** They are absolute imports such as `json` and `re`, not the project's internal calls or dependencies. Proxy Chain Completion means rebuilding a forwarding chain to a library, which is a weak stand-in for cross-file reasoning about project code.
3. **The treatment includes obfuscation.** It uses random filenames and aliases such as `_lll_reit`, although App. A.4 says the design avoids testing robustness to obfuscation. Renaming target files also breaks memorized file paths. The paper cites the SWE-bench memorization result [25] but never separates lost memorization from lost reasoning.
4. **No variance estimates.** There are no repeats, seeds, confidence intervals or tests on the resolved rates, and sampling uses the default temperature. Several key differences come down to a handful of instances.
5. **"Hints" describe the benchmark generator, not each instance's structure.**
   - They include the naming prefixes and the fact that decoys exist.
   - Sec. 5.2 describes them as giving "the roles of the perturbed files, and the key structural relations needed for solving the task". That overstates what App. A.7 and Fig. 8 show.
   - The large gains show that telling the agent the generator's rules helps. They do not show that pushing instance-specific structure helps.
6. **RepoAnchor is not compute-matched.** It runs two stages, each with its own budget, and it bundles an instruction to distrust surface cues. There is no ablation, such as two stages with no summary, or one stage with the same instruction.
7. **"Exploration drift" is partly built in.** The perturbed repositories contain more files by construction (proxy chains, decoys, JSON files), so agents have to read more. The shift in transitions is small (explore → edit −0.04 for GPT-5).
8. **Nothing about graphs or small models.**
   - No code-graph tools.
   - The related-work section never mentions graph-based localization agents.
   - No small or quantized model, and no manipulation of the context limit.
9. **Decoy-following is never measured.** The paper does not report how often agents read or edit a decoy file; it reports only pass/fail.

## Assumptions the paper does not test

- **That the perturbations preserve meaning for the agent's reasoning,** beyond the tests passing. File names and lexical cues do change.
- **That the drop reflects context reasoning,** rather than lost memorized paths or lost meaning in names.
- **That hints work by supplying structure,** rather than by warning the agent that decoys exist.
- **That INSTRUCTION.md is accurate.** No error is ever planted in it, even though stage 2 is told it "may be wrong".
- **That more exploration with fewer edits is a failure ("drift")** rather than appropriate caution.

**Implications for our design**
- **Cite it as the closest end-to-end repair evidence on two points:**
  - decoy files near the true target hurt (its largest single perturbation);
  - pushed structure helps a lot.

  Position our design as the information-matched, forked test that this paper's design cannot provide.
- **Treat the hint confound as a warning for our push arm.** The pushed text must carry exactly the graph facts that the pull tool returns. Otherwise a push gain could come from extra information or framing, such as being told that decoys exist.
- **Measure decoy-following directly.** Count whether the next read or edit hits the decoy's target, against a base rate. This paper never reports it.
- **Reuse its trajectory measures as secondary outcomes.**
  - Files whose contents were exposed, rather than merely listed, is a sensible definition of "visited".
  - Explore → edit transitions are a usable behavior metric.

## What it does NOT do that the idea needs

- No organizers' code graph or any other graph tool. No pull-vs-push contrast with the same graph facts. No presentation variants (bare names vs signature plus file:line).
- No planted false relation in the agent's context. No rate of following a decoy, compared against a true-graph base rate.
- No saved-state forks, shared seeds or short continuations. No per-pair statistics.
- No small quantized model under a hard limit of about 16k tokens.
- No test of whether stated beliefs or tool calls track actual use.
- No market agents.
