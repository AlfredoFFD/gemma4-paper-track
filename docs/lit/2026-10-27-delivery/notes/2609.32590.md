# Retrieved but Not Delivered: Multimodal Memory Delivery for Long-Term Agents

- **arXiv:** 2609.32590, v1 (26 Sep 2026, cs.CV). Version read: v1 (arXiv HTML full text, 2,917 lines, and the 32-page PDF).
- **Authors:** Yuhang Jiang (corresponding; the work was done during an internship at the Huawei Pisa Research Center), Qingwei Liao, Kaize Yin, Xingling Liu, Luca Cuomo, Silvio Bacci (Huawei Technologies).
- **Release:** code and the per-question and per-probe outputs "will be released on publication" (Reproducibility Statement). Project page: avalon-s.github.io/DeliverMem. Nothing can be re-derived yet.
- **checked:** full-text

## Claim (key numbers and where they are)

Between retrieving a memory and answering from it there is a separate stage, delivery: what of the retrieved records reaches the model, and in what form. On MemLens, with the retrieved set held fixed, delivery has more headroom than retrieval.

- **Delivery vs retrieval** (Qwen3-VL-8B, MemLens 32K, 173 non-refusal questions; Table 1, Figure 1, Section 4):
  - Delivering the gold messages' original pixels instead of withholding them gains +13.87 points (31/7, p = 1.2×10⁻⁴).
  - Replacing the retriever's ten messages with the gold messages, pixels on in both, gains +2.31 (17/13, p = 0.58).
- **Scale** (Table 15, Section 4, Appendix E.1). Delivery stays the larger term at larger backbones, but the gap narrows:
  - Qwen3-VL-30B-A3B: +15.61 vs +9.83. Qwen3-VL-32B: +17.92 vs +11.56.
  - The delivery:retrieval ratio goes 6.00×, 1.59×, 1.55×.
  - The gap between the two terms is significant only at 8B (p = 0.0078; p = 0.18 and 0.14 at the larger two).
- **The pixel effect is content, not image tokens** (Table 12, Appendix D.3):
  - Another question's photograph scores exactly what no photograph scores (+0.00, 6/6).
  - Against a phase-randomised image with the same pixel statistics, the content-specific value is +11.56 (28/8, p = 0.0012).
- **It sits in one question type:** +40.98 on the 61 information-extraction questions (28/3), and about zero on the other three types (Table 13).
- **Delivery decisions, each against a control that changes only that variable** (Table 4):
  - (D2) A readable tag stamped into each image: +11.85 over a constant tag and +9.88 over no tag on DMV-Bench (10/10 chains, p = 0.002); +0.51 on MemLens (4/3, p = 1.00).
  - (D3) Accurate dates vs permuted dates: +13.92 on 194 temporal questions (31/4, p = 3.5×10⁻⁶).
  - Binding (which image follows which message): +6.36 (14/3, p = 0.013).
- **Wrong dates are worse than none:** -5.67 on temporal questions (14/3, p = 0.013; Appendix E.7).
- **System result, with nothing trained** (Table 2):
  - MemLens: 51.28 / 44.10 / 42.05 / 38.97 at 32K / 64K / 128K / 256K, against the best published memory agent's 32.82 / 31.28 / 31.28 / 30.77.
  - The delivered input is 10× to 73× smaller than the full context.
- **DMV-Bench system result** (Tables 3 and 16):
  - 88.2 to 93.3 success, against DualMem's published 65.1 to 82.7.
  - Same-batch paired gains: +7.63 to +22.62.
- **Failures with the target in context** (Appendix D.6). On DMV-Bench, where retrieval recall is 98.4 to 100%:
  - 98% of DeliverMem's failures pick a neighbour while the target is in context.
  - The agent's trace names the target's object and colour in 94% of those.

## C2 in detail: what "delivery" is and how it is compared

- **Definition.** The answer is a = M(q, D(R(q, S))) (Section 1), with store S, retriever R and answering model M. D is the step that turns retrieved records into the tokens and pixels placed in the prompt.
  - In the paper's terms, retrieval decides which memories are accessible, and delivery decides which information in them the model can use.
  - Delivery's decisions are modality, identity, temporal position, binding, order and count. The paper measures the first three plus binding, fixes order in every control, and sweeps count (K; Appendix E.5).
- **Delivered vs retrieved-only.** "Retrieved-only" is D₀: the same retrieved messages delivered without their images (Section 4; Appendix C.1, conditions oracle10_noimg and cap10_noimg).
  - D₀ is not a caption. The image is simply dropped.
  - Table 1 is a 2×2:
    - retrieved set: gold (R*), which is the gold messages in conversation order, cut or padded to K = 10 with the text channel's top other messages; or the text-channel retriever (R), top 10;
    - pixels delivered or withheld.
  - ΔD = A(R*, D) - A(R*, D₀) and ΔR = A(R*, D) - A(R, D) (Equation 1).
  - Appendix F.1 lists which cells come from which run. All cells come from the first run, except retrieval without pixels, which was scored in a second run alongside a re-run that matched the first on all 173 questions.
- **Is content held fixed?** The record set is; the information is not, by design.
  - Held fixed within each contrast: the question set, the answering model, the benchmark prompt template, the judge, the retrieved message set, the message text, K and the order.
  - In ΔD, removing the pixels removes information on purpose.
  - The counterfactual-image ladder then fixes the number of image slots and varies only pixel content (Table 12).
  - The (D2) contrasts fix items, text, order, budget, stamp geometry and dates, and vary only whether the mark is unique. One pair is exactly token-matched, with byte-identical text (Appendix C.3).
  - The "tag in pixels vs tag in text" contrast moves the same identity information between channels (Appendix C.3).
  - The date permutation keeps the set of date values and breaks only the mapping.
- **Push only.** In every condition the pipeline places memories in the prompt.
  - On MemLens the model makes one call with ten delivered messages.
  - On DMV-Bench the agent browses a storefront, and a block of five recalled items is injected at each step (Appendix D.2).
  - The model never queries memory through a tool. There is no pull arm.
- **Models.**
  - MemLens: Qwen3-VL-8B (main), plus Qwen3-VL-30B-A3B (mixture of experts, 3B active) and Qwen3-VL-32B (Table 15). The judge is the benchmark's own, Qwen3-VL-235B-A22B.
  - DMV-Bench: Qwen2.5-VL-7B (served locally) and Gemini 2.5 Flash (API).
  - Encoders: siglip2-base-patch16-384 for images; bge-small-en-v1.5 for MemLens text; all-MiniLM-L6-v2 over Gemini captions for DMV-Bench text (DualMem's channel).
- **Effect sizes.** All are paired: a sign test on discordant pairs on MemLens, and an exact cluster permutation over chains on DMV-Bench.
  - Table 1: ΔD is +13.87 (31/7) at R* and +14.45 (30/5) at R. ΔR is +2.31 (17/13) with pixels and +2.89 (15/10) without. The interaction is -0.58 (12/14, p = 0.85).
  - Scale: see Table 15 above.
  - Content ladder (Table 12; Δ = oracle10 minus the condition):
    - tile scramble +6.94 (17/5, p = 0.017);
    - phase-randomised +11.56 (28/8);
    - decoy photograph +15.03 (33/7);
    - no image +15.03 (34/8).
  - Identical identity information presented differently (Appendix C.3; Table 10):
    - Tag in pixels vs in text: +7.89 at J = 10 (9/10 chains, p = 0.0039) and +8.73 at J = 5.
    - Neither channel alone does much: stamp only +1.33 (p = 0.48), instruction sentence only +3.08.
    - Both together give +10.97, an interaction of +6.56.
  - Retrieval-side reference points: choosing the ten messages without the query, at the same budget, costs 27 to 34 points (Table 20). The retrieval term is small only relative to a good query-conditioned retriever.

## Method (enough to reproduce)

**MemLens pipeline (Table 6, Appendix A.2).**
- **Store:** every message with its images, 32K to 256K tokens per conversation.
- **Text channel:** bge-small-en-v1.5 on the message text.
- **Image channel (R1):** siglip2-base-patch16-384 on the whole image plus a 2×2 grid of tiles with 25% overlap (Figure 5), scored by MaxSim against the query.
- **Fusion:** image scores are min-max normalised within the question and averaged with the text score. A message without an image scores 0.5 on the image channel.
- **Budget:** K = 10 messages. The K sweep gives 40.00, 46.67, 51.28 and 51.28 at K = 3, 5, 10 and 20 (Appendix E.5).
- **Prompt:** the benchmark's evaluator prompt verbatim, including its refusal instruction and the question date. The delivered items go between its head and tail (Appendix D.2).
- **Delivery components:**
  - (D1) the original images;
  - (D2) a short tag (M1, M2, ...) stamped in the top-left corner of each image, plus an instruction that names the tags, says M1 is the most relevant, and asks the model to identify items by tag rather than by counting;
  - (D3) the message timestamp in brackets.
- **Scoring:** the benchmark judge's binary score. It is reported over the 195 canonical questions or over the 173 non-refusal ones. SubEM is a second metric.

**DMV-Bench pipeline (Table 6, Appendix A.1-A.2).**
- **Task:** an agent browses a simulated storefront over J sessions (J = 5, 10, 15, 50).
  - One product photo carries a small composited cue: a colour-object pair that is absent from the page text and covers a median 1.7% of the frame (Appendix E.9).
  - A later recall probe names the cue, and the agent must navigate back to that product.
  - Success means the agent opens the exact product page. There is no judge.
- **Base system:** DualMem, the benchmark's dual-bank method, at its best fusion weight α = 0.75.
- **What DeliverMem changes:**
  - only the step that assembles what the model receives (five recalled items, the benchmark's budget);
  - R1 tiles in place of DualMem's whole-image vector;
  - a pixel tag (D2);
  - [seen #k of N] ordinals (D3).
- **Captions:** rebuilt with Gemini 2.5 Flash. They name the cue in 16.1% of cases, against the benchmark's reported 16.5%.
- **Unit of analysis:** probes are nested within chains (one chain per seed), so the chain is the unit.

**Controls (Appendix C.1, C.3, D.3).**
- **Shuffled tags:** the same tag set, stamps, dates and instruction; only the tag-to-image map is permuted. The delivered text still numbers items (1), (2), (3) in rank order, so position leaks rank.
- **Constant tag:** the same two-character symbol on every image. The sentences promising per-image tags are replaced by ones saying the marker is identical on every item, without calling it useless.
- **No tag; tag in text:** in the tag-in-text variant the image is byte-identical to the stored one.
- **Dates:** accurate vs a value-preserving permutation vs none.
- **Binding:** permute which image follows which message.
- **Image ladder:**
  - oracle10_scramble: 16 quarter-scale tiles permuted;
  - oracle10_phasescram: Fourier phase randomised, then rank-remapped so the per-channel histogram is exact;
  - oracle10_decoy: another question's photograph, drawn without replacement;
  - oracle10_noimg: no image.
- **Equal budget:** ten messages chosen by recency or at random, through the same pipeline (Table 20).

**Statistics.**
- **MemLens:** paired per question, with an exact two-sided sign test on discordant pairs. W/L counts are reported. A Bonferroni correction is applied in the per-type split (Appendix D.4).
- **DMV-Bench:** the mean of per-chain accuracies, tested with an exact cluster permutation over all 2^m sign assignments. The floor is p = 0.002 at 10 chains and 0.031 at 6.
- **Runs and batches:** conditions are compared within one run where possible. A condition scored in two runs agrees with itself to about one question (Appendix F.1).
- **Seed variance on DMV-Bench:** split into binomial and residual terms (Table 21).
- **Decoding:** no temperature or sampling settings are stated anywhere for the answering models or the judge.

**Configuration selection (Appendix C.5).**
- A dev-split rule picks, per question type, between the full configuration and a baseline. It uses 594 dev questions, SubEM as the objective, and a 3-point floor.
- The headline tables use the single unfitted configuration. Selection would raise MemLens to 54.87 / 46.67 / 44.10 / 40.51.

## Setting, data, models

- **MemLens** (Ren et al., arXiv 2605.14906): long multimodal conversations at 32K, 64K, 128K and 256K tokens.
  - The canonical evaluation subset has 195 questions. The 173 non-refusal ones are 61 information extraction, 35 multi-session reasoning, 48 temporal reasoning and 29 knowledge update; the other 22 are answer refusal.
  - Per-type effects use all 789 released questions.
- **DMV-Bench** (Tang et al., arXiv 2606.27499): ten chains with Qwen2.5-VL-7B and six with Gemini 2.5 Flash. Probes per setting run from 433 (J = 5) to 48,701 (J = 50, exhaustive) (Table 9).
- **Compute:** one 32 GB GPU; Python 3.10, PyTorch 2.11, Transformers 5.15.
  - Local models are served behind an OpenAI-compatible endpoint.
  - Gemini, the larger backbones and the judge are called through hosted APIs.

## Metrics (exact definitions)

- **MemLens accuracy:** the mean of the judge's binary score, in percent. SubEM (substring exact match) is the alternative metric.
- **DMV-Bench task success:** the agent opens the exact product page.
  - Probe-pooled when compared with published numbers.
  - The mean of per-chain accuracies for paired tests.
- **ΔD and ΔR:** as in Equation 1. The delivery-matched effect is Δ = A(R, D) - A(R, D_c), where D_c changes one variable (Section 7).
- **Recall@1:** for the offline R1 analysis (Figure 5).
- **Input ratio:** median full-context tokens over median delivered tokens (Table 18).

## Results (including weak and negative ones)

**Coverage and retrieval**
- **Coverage vs use** (Section 4). The text retriever puts at least one gold message among the ten for 96.5% of questions. But it recovers only 20.2% of the gold messages a question needs, against 99.4% for the oracle. Five times the coverage buys +2.31.
- **Small retrieval-side changes** (Appendix D.5). Removing distractors (gold only) and adding the image channel each gain +4.05 (11/4 and 14/7), both inside the noise.
- **Total headroom** (Section 4): gold only vs retrieval over both channels is -1.16 under SubEM and +2.31 under the judge (18/14). Neither is significant.

**Breakdowns by question type** (Table 14)
- ΔR is +10.34 on knowledge update (6/3) and -1.64 on information extraction.
- ΔD is +40.98 on information extraction (27/2), and -2.86 and -3.45 on multi-session and knowledge update.
- No ΔR row is significant (p ≥ 0.31).
- Neither axis moves the 38 questions that need ten or more gold messages.

**Scale, abstention and metric** (Appendix E.1)
- **Abstention.** The 32B model declines 58 of the 173 answerable questions; the 8B model declines 36. Abstention rates are 20.8% (8B), 12.1% (30B-A3B) and 33.5% (32B).
- The 32B model scores lower overall (47.69 vs 51.79) while being more accurate on the questions it answers (61.74% vs 57.66%).
- **Metric dependence:**
  - At 32B the delivery:retrieval ratio is 1.71× under SubEM and 1.55× under the judge.
  - At 30B-A3B, SubEM puts the retrieval term at +5.78 (p = 0.11), against +9.83 under the judge.

**Nulls and small effects**
- **(D2) on MemLens:** +0.51 (4/3). Replacing every tag with one symbol changes 27 of 195 answers, but the score barely moves (Section 7).
- **(D3) on DMV-Bench:** +0.07 at J = 10 (29 probes gained, 27 lost) (Section 7).
- **(D2) with a shuffled map:** +2.63 (8/10 chains, p = 0.072), not significant (Section 7).
  - Shuffled but unique tags still gain +9.23 over the constant symbol, so uniqueness matters more than a correct map.
  - The constant symbol sits 1.97 points below no marker (p = 0.078).
- **R1 on MemLens:** -1.03 (4/6, p = 0.75) (Section 7, Table 7).
- **Gemini 2.5 Flash, J = 50** (Table 17, Appendix E.3):
  - Delivery adds +0.46 (p = 0.156); R1 adds +22.16. 92% of the baseline's failures there are retrieval misses.
  - Delivery recovers 30.3% of the remaining headroom on Qwen, against 5.1% on Gemini (4.8% at J = 10).
- **Tag + date over all 789 questions** (Appendix E.8): -8.62 on knowledge update and +7.22 on temporal reasoning. Within Table 7's batch, tag + date nets +1.03 (two questions).

**Comparisons with long-context reading**
- **Same backbone reading the whole conversation** (Table 18): DeliverMem is +0.51 at 32K, -3.59 at 64K and +7.69 at 128K.
- **Frontier models reading everything** still score higher at 32K (Table 8): Gemini-3.1-Pro 55.38, Qwen3-VL-30B-A3B 58.46, Qwen3.5-122B 63.59.

**Where the 32K margin comes from** (Section 6)
- 19 of the 36 margin questions are refusal questions. DeliverMem answers all 22 refusal questions correctly, even with pixels withheld; MemAgent-7B gets 13.64%.
- On the 173 non-refusal questions the margin is +9.83.

**Seed variance on DMV-Bench** (Table 21)
- The observed SD is 8.01 points at J = 5 (43 probes per seed) and 3.15 at J = 50.
- The residual, 3 to 5.5 points, barely shrinks with more probes.

## Limitations: the authors' (Section 8)

1. Delivery granularity (a crop, the whole frame, or both) is not measured. MemLens images have no defined relevant region, and on DMV-Bench the axis interacts with R1.
2. Per-type effects use all 789 questions, because the 195-question subset has only 29 knowledge-update questions.
3. Every measurement is on images (Appendix C.2 argues the logic carries to audio and video, untested).

## Limitations: mine

1. **"Text-only" delivery here means no picture at all.**
   - D₀ drops the image, with no caption or other textual proxy (Section 4, Appendix C.1).
   - Text-first memory systems deliver captions: four of the seven published MemLens agents use BLIP-2 captions (Appendix A.4).
   - So +13.87 is pixels vs nothing. The gain over a caption, which is the practical alternative, is never measured on MemLens.
2. **"Delivery beats retrieval" depends on the reference points.**
   - ΔR runs from a good query-conditioned retriever up to the oracle. From query-free selection at the same budget, the retrieval term is 27 to 34 points (Table 20), larger than ΔD.
   - The ratio falls from 6.00× to 1.55× with scale, and the gap is significant only at 8B.
   - The body hedges correctly ("relative to current practice on each side"). The abstract reads broader.
3. **On MemLens, the tag, date and region index add nothing net at 32K.**
   - The full DeliverMem row and the default-index two-channel row without tag or date both score 51.28 overall and 45.09 on non-refusal questions (Table 7).
   - The 32K lead over published agents comes from delivering pixels with a query-conditioned K = 10 retriever, and from refusal questions.
   - 19 of the 36 margin questions are refusals, answered 22/22 even with pixels withheld. The benchmark prompt's refusal instruction (Appendix D.2) likely helps here.
   - This is not a flaw in the controlled contrasts, but the abstract credits the whole package.
4. **Decoding is unstated.**
   - No temperature or sampling settings are given for the answering models or the judge.
   - Test-retest at about one question (Appendix F.1) partly covers this.
5. **Power.**
   - At n = 173 with an exact sign test, effects of roughly 6 points and up are resolved.
   - +2.31 (17/13) is indistinguishable from zero, which is not the same as zero.
   - Per-type subsets have 29 to 61 questions.
6. **"The trace names the target" mostly restates the probe.**
   - The recall probe itself names the cue (Appendix A.1). So a trace naming the target's object and colour (93.2% and 94.0%, Appendix D.6) shows the agent knows the request, not that it found the right image.
   - The informative facts are two: the action follows the trace's stated item in 95 to 98% of cases, and that stated attribution is wrong.
7. **The judge is from the same family as the answering models.**
   - Qwen3-VL-235B-A22B judges Qwen3-VL answers, and judge bias is not examined.
   - The retrieval term moves with the metric: at 30B-A3B it is +5.78 under SubEM and +9.83 under the judge.
8. **Item order may differ between R and R\*.**
   - oracle10 lists the gold messages in conversation order. The order of the retriever's set is not stated, presumably rank order.
   - Given the strong first-position pull seen on DMV-Bench (Appendix D.6), the ΔR arms may differ in order as well as content. The ΔD arms share order.
9. **The DMV-Bench run structure is under-specified.**
   - Probes are "shared" across conditions, yet the stored history depends on how much of the storefront the backbone browses: 80 to 157 images at J = 50 (Appendix E.6).
   - Whether histories are regenerated per condition is not said.
10. **No code yet.** No headline number can be re-derived from per-question outputs today.

## Assumptions the paper does not test

- That letting the model query memory itself, a pull arm, would not change the picture.
- That pixels beat a caption, as opposed to beating nothing.
- That wrong attributes are adopted. Nothing checks whether answers repeat a permuted date or describe the decoy image.
- That order is neutral across the retrieval conditions.
- That results hold for non-Qwen families on MemLens (all three backbones are Qwen3-VL) and for modalities other than images.
- That the "conditions (i)-(iii)" rule predicts nulls ahead of time. It is fitted to explain the nulls observed here (Sections 1 and 7).

## What it does NOT do that the idea needs

- **No software engineering.** No code, code graph or issue repair, and no Gemma 4, 4-bit or 16k-context regime.
- **No pull arm.** The model never queries memory through a tool, so the idea's core contrast, pushed vs pulled, is absent. All of its delivery contrasts are among pushed forms.
- **No planted relation with a known destination.** No following rate against the base rate of visiting that destination when the information is true.
- **No forks from a saved agent state, and no next-step measure after a manipulation.** DMV-Bench scores only the probe's final choice.
- **No cross-domain test.**

What it gives the idea:
- **Positioning and vocabulary.** "Delivery" is a named stage between retrieval and use, with a citable decomposition. This paper varies the form of memory that is always pushed. The idea varies whether graph structure is pushed or must be pulled, and whether it is true.
- **Controls worth copying:**
  - conditions specified as byte differences;
  - token-matched pairs;
  - a control that destroys content but keeps surface statistics (phase scrambling here; for a code graph, the same names and format with randomised edges);
  - a test-retest check.
- **A design hazard.** When items lack readable identities, wrong picks go to the first-listed item. In the push arm, the decoy's rank in the pushed block must be randomised or counterbalanced, and logged. File:line identifiers are the code analogue of the D2 tags.
- **A conditionality rule to pre-register.** A presentation choice helps only when the task needs what it supplies and the context lacks it. So effects of signatures or file:line should be pre-registered by task type.
- **Wrong vs absent depends on the attribute.** A wrong date hurts relative to none (-5.67); a wrong image does not (0.00). The decoy analysis should report decoy vs no-graph as well as decoy vs true.
- **Power calibration.** At n = 173, paired, effects of +6 to +14 points resolved and +2.31 did not. With about 106 tasks, expect the same or a coarser floor.
