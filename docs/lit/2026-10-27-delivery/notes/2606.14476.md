# When the Tool Decides: LLM Agents Defer Blindly to Graph Neural Network Tools, and Stronger Backbones Defer More

- **arXiv:** 2606.14476, v1 (12 Jun 2026, cs.AI). Version read: v1 (arXiv HTML full text and the 9-page PDF).
- **Authors:** Zhongyuan Wang, Pratyusha Vemuri (raptorX.ai). Written for a TMLR audience (Section 1).
- **Release:** the paper says the frozen-GNN training, the four arms, budget enforcement, metrics, results JSON and seeds are released. No URL appears in the text.
- **Cited by:** 2609.05587, as the graph-tool instance of tool-conflict work (its Section 2).
- **checked:** full-text

## Claim (key numbers and where they are)

A ReAct agent that is given a frozen GNN as a tool does not weigh the tool's output; it copies it.
- Qwen2.5-7B on ogbn-arxiv agrees with the raw GNN on 0.976-0.992 of nodes across three local-homophily bins (5 seeds, 50 nodes/bin; Table 1, Section 4).
- With the tool available, the agent's answers match its own tool-free answers only 0.17-0.37 of the time at 7B, and 0.07-0.20 at 3B (Section 4).
- In 83% of 7B queries the agent makes exactly one call (the label). It never asks for the anomaly score that flags when the label is unreliable (Section 4; text only, no table).
- Among models that can use the tool, agreement rises with size: 0.60, 0.97 and 0.98 for 1.5B, 3B and 7B (Table 2, Section 5).
- The cost of deferring does not shrink with size. The per-node oracle gap goes from 0.12 to 0.22 at high homophily between 3B and 7B (paired t=9.1, positive in 5/5 seeds; Table 3, Section 6). At 7B a neighbour-label tool beats the GNN at high homophily (0.81 vs 0.71), and the agent defers to the GNN anyway (Table 1).
- A selective-invocation gate helps at high homophily (0.71 to 0.83) and hurts elsewhere, for no net gain (0.481 to 0.475). Held-out estimators bound the best gate over four standard features to recovering 1/6 to 1/3 of the 0.175 oracle headroom (Section 7).
- The WikiCS replication reproduces the copying: agreement 0.96-1.00 (Table 4, Section 8).
- The extreme magnitude is partly Qwen-specific: Mistral-7B and OLMo-2-7B agree with the GNN only 0.53 and 0.60 of the time (Section 9).

## Method (enough to reproduce)

**GNN tool (Appendix A).**
- A 2-layer GCN (hidden 128) with a reconstruction head, trained 200 epochs on each dataset's official training split.
- Best-validation checkpoint, then frozen. Retrained per seed.

**Arms (Section 3, Appendix A).** All arms share one per-query budget: 5,000 prompt+generation tokens (counted with the backbone's own tokenizer) and 6 tool calls.
- **A1, agent + GNN tool.** Three separate calls bound to the query node:
  - `gnn_predict()` returns "class=c conf=p".
  - `gnn_anomaly()` returns a reconstruction anomaly score, described to the agent as "higher means the GNN is more likely wrong on this node".
  - `gnn_link(neighbour-id)` returns a link probability.
- **A2, agent + navigation tool.** Modeled on AgentGL's textual graph operations, without reusing its code.
  - `neighbors()` returns up to k=10 neighbour ids, each with its training label if the neighbour is in the training split ("?" otherwise; no neighbour text).
  - `degree()` returns the node degree.
- **A3, frozen GNN alone.** Charged one call.
- **A4, agent with no graph tool.** The system prompt asks for one `ANSWER: <class id>` line.

**Agent loop (Appendix A).**
- Text-protocol ReAct with regex-parsed `ACTION:` / `ANSWER:` lines, at most 4 steps.
- Each tool observation is fed back as a user turn.
- When the budget runs out, or after the last step, a forced-finalization turn asks for an answer.
- Parsing takes the `ANSWER:` line, else the last in-range integer, else falls back to class 0. This only affects 0.5B and Mistral.
- The A1/A2 system prompt (Chinese; English translation in Appendix A) tells the agent to call tools to gather evidence first, then answer. Tool invocation is therefore instructed, and the paper treats it as compliance. The measured behavior is adopting the output.

**Task template.** The paper's title+abstract truncated to 500 characters (English, embedded in the Chinese scaffold), plus the candidate list of `id: label-name`.

**Decoding and serving.**
- Temperature 0.7, top-p 0.9, max 256 new tokens per turn.
- Seeds fix GNN training and node sampling but not LLM decoding.
- Qwen 1.5-7B multi-seed runs are served by vLLM, checked equivalent to HF transformers on the seed-0 phase-1 grid. 0.5B and Mistral run on transformers.

**Sampling.**
- Test nodes are stratified by ground-truth local homophily, the fraction of same-label neighbours: low <0.3, mid [0.3, 0.7), high >=0.7. The bin is never shown to the agent.
- 50 nodes per bin per seed, 5 seeds; a seed is a retrained GNN plus a resampled node set.
- Node samples are shared across backbones within a seed, so the backbone comparisons are paired.

**Gates (Section 7).**
- A post-hoc purity gate routes a node to A2 when its training-label neighbourhood purity exceeds τ=0.4 (chosen on seed 0), and to A1 otherwise.
- A learned router over four features (purity, GNN confidence, degree, neighbour disagreement) picks one of {GNN, A2, A4}. It is evaluated leave-one-seed-out over the 750 stratified nodes.
- Ceiling estimates:
  - a leave-one-seed-out kNN best-arm policy (k=31, standardized features)
  - a median-binned cell policy
  - both compared against feature-shuffled nulls

**Replication and cross-family runs.**
- WikiCS: 11.7k nodes, 10 classes, edge homophily 0.66. 7B only, 3 seeds, 40 nodes/bin.
- Cross-family: Mistral-7B-Instruct and OLMo-2-7B-Instruct on a shared frozen GNN and node sample (3 seeds, 60 nodes), under a matched English scaffold. Qwen-7B under the same English scaffold is the control.

## Setting, data, models

- **Data:** ogbn-arxiv (169k nodes, 40 classes, citation graph, title+abstract node text) and WikiCS.
- **Models:** Qwen2.5-Instruct 0.5B / 1.5B / 3B / 7B; Mistral-7B-Instruct; OLMo-2-7B-Instruct. All served locally on a single GPU.
- **Task:** single-node classification, at most 4 ReAct steps. No code, no repository, no multi-step environment.

## Metrics (exact definitions, Section 3)

- **Accuracy** per arm.
- **Agreement** = Pr[A1 prediction = A3 prediction]. This is the "parrot" measure.
- **Oracle gap** = acc(per-node best of {A1, A2, A4}) - acc(A1). It is non-negative by construction, and the paper says only its magnitude is informative.
- **Tool calls:** mean count at low homophily. This separates incapacity (about 0 calls) from deference.
- Reported as mean ± SE over seeds.

## Limitations: the authors'

- **Scope.** Node classification on ogbn-arxiv and WikiCS, Qwen2.5 family, GCN tool. The paper says magnitudes may not transfer (Section 9).
- **Saturation.** The agreement trend saturates by 3B, so the load-bearing contrast is 1.5B vs 3B+. 0.5B is seed 0 only, and there are no backbones beyond 7B (single GPU).
- **Observational trend.** The capability trend is observational. The paper does not isolate a mechanism and names "the GNN tool's output dominating the agent's context" as an open mechanism (Section 9).
- **Gates.** No gate closes the gap. The ceiling is empirical over four features, not a proof.
- **Instructed invocation.** The scaffold instructs tool use, so the paper poses selective invocation outside the agent.
- **Language.** The scaffold is Chinese. The English-scaffold control on Qwen-7B shows the language is not what produces parroting.
- **Other families.** Non-Qwen families defer only partially.
- **Untested.** Heterophilous text-attributed graphs, and an A2 arm with neighbour text.

## Limitations: mine

1. **The tool's output is in the answer space.** `gnn_predict` returns the class id itself, so copying it is the cheapest valid policy under a one-line ANSWER protocol. The paper shows answer-copying. It does not show that an agent follows a structural relation that still requires a further action (where to read, what to edit).
2. **Demand characteristics.** The prompt says to call tools first, then answer, and the agent has a 4-step cap and a 256-token turn limit. Deference may be partly instruction-following and format pressure.
3. **The oracle gap mixes in sampling luck.** It is a per-node max over three arms sampled at T=0.7 without seeded decoding, so part of the gap is best-of-3 luck rather than cost of deference. There is no control, such as an oracle over three resamples of A1. The mid-bin gap of 0.18, with A1 and A2 near 0.44 and 0.40, looks especially exposed to this.
4. **Agreement is never conditioned on the GNN being wrong.** From Table 1 bin means, P(agent = GNN | GNN wrong) is at least (agree - acc)/(1 - acc): 0.966 (low), 0.957 (mid) and 0.972 (high). This is my arithmetic. So the agent follows wrong tool outputs at least about 96% of the time.
5. **No base rate.** The paper reports A1-vs-A4 agreement but not A4-vs-A3: how often the agent lands on the GNN's label with no tool. For the C3-style question, "how often would it pick that target anyway?", this is the missing baseline.
6. **Errors are natural, not planted.** They are concentrated in hard, low-homophily nodes, so "following a wrong output" is confounded with node difficulty. There is no injected error on easy nodes.
7. **Small n.** 50 nodes/bin × 5 seeds; paired t over 5 seed means (df=4); WikiCS has 3 seeds × 40 nodes.
8. **Sampling noise.** Decoding is sampled and not seeded, so single-node behavior carries sampling noise. All pairing is at the node level.

## Assumptions the paper does not test

- That high agreement means obedience rather than warranted agreement. The tool's truth is never manipulated.
- That deference carries to tools whose output is evidence (relations, neighbours, locations) rather than the answer itself.
- That deference persists when invocation is the agent's free choice. Here it is instructed.
- That the format or placement of the tool output does not matter. The label is always pulled by a call, never pushed into the prompt, and never shown without confidence.
- That the finding holds over longer horizons, with edits, tests or feedback. Only ≤4 steps of single-shot classification are tested.

## Overlap with the idea

| Component | Coverage | Where, and what exactly |
|---|---|---|
| C1 Setting | partly | Small open models with a graph tool under a hard budget (5,000 tokens, 6 calls, ≤4 steps): Section 3, Appendix A. But the task is node classification on citation and Wikipedia graphs, not a coding agent, not issue repair, not a code graph. Gemma is not tested. |
| C2 Delivery | not | The graph signal is only pulled through instructed tool calls. It is never pushed into context, and presentation is never varied. Adjacent: three signals are exposed as separate calls, and 83% of 7B queries make one call and never fetch the anomaly signal (Section 4). |
| C3 Truth | partly | The tool is naturally wrong on 29-70% of nodes (A3 accuracy 0.30/0.44/0.71; Table 1), and agreement is 0.976-0.992, which implies following wrong outputs at least about 96% of the time (my bound). There is no planted decoy, no agreement conditional on GNN error, and no same-target base rate. |
| C4 Method | not | The arms run on the same sampled nodes per seed, and those samples are shared across backbones (Table 3 caption), analysed with paired t over 5 seeds. There are no forks from a saved agent state, no shared prefix, and no seeded decoding. |

The tool overrides the agent's own reasoning (A1-A4 agreement 0.17-0.37 at 7B). The queryable anomaly signal goes unused. | C6 Cross-domain | not | No market agents. |

## What it does NOT do that the idea needs

- **No software engineering.** No code graph, no repository, no edit or test loop, and no measure of where the agent reads or edits next.
- **No planted relation and no base rate.** No planted wrong-but-plausible relation scored against how often the agent visits the same target when the graph is true.
- **No delivery or presentation manipulation.** Nothing is pushed or pulled differently, and the format of the graph signal is never varied.
- **No state-level counterfactuals.** No forks from one saved agent state with a shared prefix and seed.
- **A different model and regime.** No Gemma, no 4-bit quantization, no 16k-context regime.
- **An answer-copying tool.** The tool returns the answer, so it cannot separate following a hint from copying an answer.

What it gives the idea:
- A graph-ML-venue reference point a graph-ML judge will know: agents defer to graph tools.
- An explicit open question in its Section 9 (does the tool output dominate the context?) that the idea's push vs pull forks answer directly.
- Evidence that queryable signals go unused (the anomaly call).
